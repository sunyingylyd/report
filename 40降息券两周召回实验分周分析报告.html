一、背景与口径

01

实验设计。

1,000 名流失用户（结清后流失 8~162 天，平均 31.6 天），7-16 发 40% 降息券，有效期 14 天（覆盖 07-16~07-29 前两周）。

02

观察窗口。

07-16 发券至 08-27 共 43 天，按周拆分：第一周（07-16~22）、第二周（07-23~29）、第三周（07-30~08-05）、第四周+（08-06~08-27）。前两周为券期内，之后券过期。

03

核心口径。

提单率 = 窗口内提单去重用户数 / 1,000；盈利率 = (Σrepaid−Σremit)/Σremit（is_remit=1 且 is_due=1）；逾期率 = status=8 / is_due=1（按单数）。

第二周逾期率（22.81%）与第一周（22.58%）几乎一样，问题不在逾期率，而在「利息收入缩水 + 坏账损失没缩小」。

01

利息收入大幅缩水（主因，-13.1 万）。

第二周正常结清订单只有 88 单（vs 第一周 120 单），且件均更小（6,123 vs 7,386）——「赚利息的盘子」又少又小。

02

坏账损失没跟着缩小（只减 1.1 万）。

第二周逾期单数少（26 vs 35），但逾期订单件均更大（7,941 vs 6,928）、回款率更低（22.37% vs 29.13%），单均损失更高（6,165 vs 4,910），总损失几乎追平第一周。

03

复贷「高息高坏账」、新提单「低息低坏账」，净盈利率殊途同归。

复贷老用户借高息产品（利息率 56.22%）但逾期金额占比高（36%）；新提单借低息小额（37.13%）但坏账占比低（24.6%）。两者净盈利率都落在 8.6% 附近——不能只看逾期率，要结合利息率和逾期金额结构。

五、一周券 vs 两周券：应该发多久

核心证据：券第二周拉来的是「犹豫型差用户」，而无券时第二周自然回流的是「优质用户」。

01

券第一周拉来优质用户。

40% 券第一周盈利率 16.32%、提单率 15.90%；30% 券实验第一周盈利率 19.18%、提单率 32.73%——券第一周快速转化优质用户。

02

券第二周拉来犹豫型差用户。

40% 券（两周券）第二周盈利率腰斩至 8.64%，且是「利息缩水 + 坏账不缩」的结构性差，并非样本波动。

03

无券时第二周自然回流的是好用户。

30% 券实验对照组（无券）第二周盈利率 19.59%，远高于发过券的实验组第二周（7.48%）和 40% 券第二周（8.64%）。

04

结论：发一周券更合适。

券的增量价值集中在第一周；第二周继续发券，边际收益低（拉来差用户、盈利率 8.64%），边际成本高（40% 降息让利）。第二周不发券，让用户自然回流，质量反而更好（19.59%）。

六、核心结论与建议

A

第一周提单的是优质用户，第二周是犹豫型差用户。

数据：第一周提单率 15.90%、盈利率 16.32%；第二周 11.60%、8.64%。同一券期内，仅「提单时点早晚」就拉开 7.68pp 盈利率差距。

B

第二周盈利率低 = 利息收入缩水 + 坏账损失不缩。

数据：利息收入 -37%（-13.1 万），坏账损失仅 -1.1 万。不是逾期率问题，而是「赚利息的盘子变小、亏本的窟窿没跟着缩」。

C

券提升提单率（+7.46pp），但降息拖累盈利率。

数据：30% 券实验第一周提单率 +7.46pp、盈利率 -3.11pp。券是「量增利减」的权衡。

D

建议发一周券，不做两周券。

第二周券拉来差用户（8.64%），不如自然回流（19.59%）。把券资源集中第一周做足触达，第二周停止降息、改用低成本触达或风控升级。

附录：完整 PGSQL

以下代码覆盖本报告的分周统计、盈亏分解、复贷/新提单拆分、券期内外对比。

模块一：分周统计（提单率 / 盈利率 / 逾期率）
-- 40% 降息券测试（user_40pct_discount_7_16，1000 人，券期 14 天）
-- 提单率 = 窗口内提单去重用户数 / 表总用户数(1000)
-- 盈利率 = (Σrepaid - Σremit) / Σremit，仅计 is_remit=1 且 is_due=1
-- 逾期率 = status=8 / is_due=1（按单数）
WITH test_users AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.user_40pct_discount_7_16
)
SELECT
    CASE
        WHEN o.apply_date BETWEEN '2026-07-16' AND '2026-07-22' THEN '第一周'
        WHEN o.apply_date BETWEEN '2026-07-23' AND '2026-07-29' THEN '第二周'
        WHEN o.apply_date BETWEEN '2026-07-30' AND '2026-08-05' THEN '第三周'
        WHEN o.apply_date >= '2026-08-06' THEN '第四周+'
    END AS 窗口,
    COUNT(DISTINCT t.user_id)                                             AS 提单用户数,
    ROUND(COUNT(DISTINCT t.user_id) * 100.0 / 1000, 2)                    AS 提单率,
    COUNT(*)                                                              AS 提单订单数,
    COUNT(CASE WHEN o.is_remit = 1 THEN 1 END)                            AS 放款订单数,
    COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN 1 END)           AS 到期订单数,
    COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1
               AND o.loan_status_code = 8 THEN 1 END)                     AS 逾期订单数,
    ROUND(COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1
                      AND o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM test_users t
JOIN wangchuanliang.order_loan_f_v2_copy o ON o.user_id = t.user_id
WHERE o.apply_date BETWEEN '2026-07-16' AND '2026-08-27'
GROUP BY 1
ORDER BY 1;
模块二：第一周 vs 第二周 盈亏分解（正常/逾期分开）
-- 盈利率低的原因：利息收入缩水 vs 坏账损失不缩
WITH test_users AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.user_40pct_discount_7_16
)
SELECT
    CASE WHEN o.apply_date BETWEEN '2026-07-16' AND '2026-07-22' THEN '第一周'
         WHEN o.apply_date BETWEEN '2026-07-23' AND '2026-07-29' THEN '第二周' END AS 窗口,
    o.loan_status_code,
    COUNT(*)                                                              AS 单数,
    ROUND(SUM(o.remit_amt)::numeric, 2)                                   AS 放款金额,
    ROUND(SUM(o.repaid_amt)::numeric, 2)                                  AS 已还金额,
    ROUND(SUM(o.repaid_amt) * 100.0 / NULLIF(SUM(o.remit_amt), 0), 2)     AS 回收率
FROM test_users t
JOIN wangchuanliang.order_loan_f_v2_copy o ON o.user_id = t.user_id
WHERE o.apply_date BETWEEN '2026-07-16' AND '2026-07-29'
  AND o.is_remit = 1 AND o.is_due = 1 AND o.loan_status_code IN (7, 8)
GROUP BY 1, 2
ORDER BY 1, 2;
模块三：第二周订单拆分（复贷 vs 新提单）
-- W1也提单(复贷) = 第一周也有提单的用户；W2新提单 = 第一周未提单、第二周首次提单
WITH test_users AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.user_40pct_discount_7_16
),
w1_users AS (
    SELECT DISTINCT t.user_id
    FROM test_users t
    JOIN wangchuanliang.order_loan_f_v2_copy o ON o.user_id = t.user_id
    WHERE o.apply_date BETWEEN '2026-07-16' AND '2026-07-22'
)
SELECT
    CASE WHEN w1.user_id IS NOT NULL THEN 'W1也提单(复贷)' ELSE 'W2新提单' END AS 类型,
    COUNT(*)                                                              AS 提单订单数,
    COUNT(DISTINCT t.user_id)                                             AS 提单用户数,
    COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN 1 END)           AS 到期订单数,
    ROUND(COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1
                      AND o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM test_users t
JOIN wangchuanliang.order_loan_f_v2_copy o ON o.user_id = t.user_id
LEFT JOIN w1_users w1 ON w1.user_id = t.user_id
WHERE o.apply_date BETWEEN '2026-07-23' AND '2026-07-29'
GROUP BY 1
ORDER BY 1;
模块四：券期内 vs 券期外对比
-- 前两周 = 券期内（07-16~07-29）；两周后 = 券期外（07-30 起）
WITH test_users AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.user_40pct_discount_7_16
)
SELECT
    CASE WHEN o.apply_date <= '2026-07-29' THEN '前两周(券期内)'
         ELSE '两周后(券期外)' END AS 窗口,
    COUNT(DISTINCT t.user_id)                                             AS 提单用户数,
    ROUND(COUNT(DISTINCT t.user_id) * 100.0 / 1000, 2)                    AS 提单率,
    COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN 1 END)           AS 到期订单数,
    ROUND(COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1
                      AND o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.is_remit = 1 AND o.is_due = 1 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM test_users t
JOIN wangchuanliang.order_loan_f_v2_copy o ON o.user_id = t.user_id
WHERE o.apply_date BETWEEN '2026-07-16' AND '2026-08-27'
GROUP BY 1
ORDER BY 1;
