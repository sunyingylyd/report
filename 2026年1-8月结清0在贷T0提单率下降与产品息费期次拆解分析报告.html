30天总体提单率明显下滑：30天累计提单率由1月的88.50%降至8月预测的81.78%，下降6.72个百分点。
当天段是下滑的核心因素：当天最早提单率下降13.70个百分点，降幅明显大于30天累计提单率；同期1—7天首次提单率由25.99%升至28.07%，8—15天由5.67%升至7.93%。
用户提单存在延后趋势：即时提单的比例持续下降，而后续7天和15天内的提单占比上升，说明用户并非完全不提单，而是从“获额后即时提单”转向更晚的提单时点。
息费与当天提单率反向变化：当天提单订单整体加权息费上升时，当天提单率持续下降。这支持息费变化可能影响即时转化的假设。
产品侧两条路径：各期次产品息费均上升；同时低息费 2 期产品结构缩小、息费更高的 3 期产品结构扩大，两者共同推高整体息费。
因果边界：当前数据是“实际提单订单”的结果，不能单独证明息费提升导致用户不提单。后续应补充获额时可见报价、额度和用户资质，做控制变量分析或随机价格试验。

四、历史成功放款次数分层验证：各客群均呈“息费升、当天提单率降”

以获额通过时点之前的成功放款次数分层，观察1月与8月的变化。该拆解将不同贷款经验的用户分开比较，用于验证“息费上升与即时提单走弱”并非只由客群混合变化造成。

分层对照结论

贷款6次及以上用户的息费增幅最低（+6.52个百分点），当天提单率降幅也最小（-9.22个百分点）。其余三类客群息费上升11.81—13.05个百分点，当天提单率下降12.15—15.69个百分点。

从分层趋势看，息费增幅较低的客群，提单率下滑也相对较少；这为两者的负向关系提供了补充证据。

解释边界

这不是价格试验。各分层内部仍可能同时发生额度、准入、风险结构、运营触达等变化，因此不能将相关性直接解读为单一因果效应。

但四类用户均出现“息费上行、当天提单率下行”，说明该现象并非仅由不同历史贷款次数客群的占比变化造成。

各客群加权息费率（月度）

所有客群的息费率在7—8月处于较高水平；6次及以上用户的上升幅度相对较小。

七、附录：完整可复现 PGSQL

按模块顺序执行。模块1生成临时表；模块2输出提单率；模块3输出期次/息费；模块4输出历史成功放款次数分层验证。

模块 1：T0 样本、获额去重、最早提单
SET TIME ZONE 'America/Belize';
CREATE TEMP TABLE settled_orders AS
SELECT user_id,serial_id,apply_time,repaid_time,repaid_date::date repaid_date
FROM wangchuanliang.order_loan_f_v2_copy
WHERE is_remit=1 AND loan_status_code=7 AND repaid_time>TIMESTAMP '2000-01-01'
AND repaid_date>=DATE '2026-01-01' AND repaid_date<=DATE '2026-08-31';
CREATE TEMP TABLE candidate_users AS SELECT DISTINCT user_id FROM settled_orders;
CREATE TEMP TABLE all_orders AS
SELECT o.user_id,o.serial_id,o.apply_time,o.repaid_time,o.loan_status_code,o.is_remit,
o.remit_amt,o.pre_amt,o.post_amt,o.total_term,o.product_no,o.loan_day
FROM wangchuanliang.order_loan_f_v2_copy o JOIN candidate_users u USING(user_id);
CREATE TEMP TABLE clean_settles AS
SELECT s.* FROM settled_orders s WHERE NOT EXISTS(
SELECT 1 FROM all_orders o WHERE o.user_id=s.user_id AND o.serial_id<>s.serial_id
AND o.apply_time<s.repaid_time AND (o.loan_status_code IN(5,8)
OR(o.loan_status_code=7 AND o.repaid_time>s.repaid_time)));
CREATE TEMP TABLE credit_days AS SELECT DISTINCT user_id,repaid_date-1 vir_date FROM clean_settles
UNION SELECT DISTINCT user_id,repaid_date FROM clean_settles;
CREATE TEMP TABLE raw_credit_pass AS
SELECT DISTINCT ON(v.user_id,v.serial_id) v.user_id,v.serial_id,v.vir_date::date vir_date,
(TO_TIMESTAMP(v.vir_unix) AT TIME ZONE 'America/Belize') vir_time
FROM wangchuanliang.order_vir_f_copy v JOIN credit_days d ON d.user_id=v.user_id AND d.vir_date=v.vir_date
WHERE v.is_pass1=1 ORDER BY v.user_id,v.serial_id,v.vir_unix DESC;
CREATE TEMP TABLE dedup_credit_pass AS
WITH a AS(SELECT *,LAG(vir_time) OVER(PARTITION BY user_id ORDER BY vir_time,serial_id) p FROM raw_credit_pass),
b AS(SELECT *,SUM(CASE WHEN p IS NULL OR vir_time-p>INTERVAL '20 seconds' THEN 1 ELSE 0 END)
OVER(PARTITION BY user_id ORDER BY vir_time,serial_id) bid FROM a)
SELECT user_id,serial_id,vir_date,vir_time FROM(
SELECT *,ROW_NUMBER() OVER(PARTITION BY user_id,bid ORDER BY serial_id DESC) rn FROM b)x WHERE rn=1;
CREATE TEMP TABLE t0_samples AS
SELECT user_id,repaid_date,credit_vir_time FROM(
SELECT c.user_id,c.repaid_date,cp.vir_time credit_vir_time,
ROW_NUMBER() OVER(PARTITION BY c.user_id,c.repaid_date ORDER BY cp.vir_time,cp.serial_id DESC,c.repaid_time) rn
FROM clean_settles c JOIN dedup_credit_pass cp ON cp.user_id=c.user_id
AND cp.vir_date=c.repaid_date AND cp.vir_time>=c.repaid_time)x WHERE rn=1;
CREATE TEMP TABLE first_apply AS
SELECT user_id,repaid_date,serial_id first_apply_serial_id,apply_time::date first_apply_date,
remit_amt first_apply_remit_amt,pre_amt first_apply_pre_amt,post_amt first_apply_post_amt,total_term first_apply_total_term
FROM(SELECT t.user_id,t.repaid_date,a.*,
ROW_NUMBER() OVER(PARTITION BY t.user_id,t.repaid_date ORDER BY a.apply_time,a.serial_id) rn
FROM t0_samples t JOIN all_orders a ON a.user_id=t.user_id AND a.apply_time>=t.credit_vir_time
AND a.apply_time<t.credit_vir_time+INTERVAL '31 days')x WHERE rn=1;
模块 2：月度提单率、累计提单率
WITH m AS(
SELECT TO_CHAR(DATE_TRUNC('month',t.repaid_date),'YYYY-MM') month,COUNT(*) sample_cnt,
COUNT(*) FILTER(WHERE f.first_apply_date=t.repaid_date) d0,
COUNT(*) FILTER(WHERE f.first_apply_date-t.repaid_date BETWEEN 1 AND 7) d1_7,
COUNT(*) FILTER(WHERE f.first_apply_date-t.repaid_date BETWEEN 8 AND 15) d8_15,
COUNT(*) FILTER(WHERE f.first_apply_date-t.repaid_date BETWEEN 16 AND 30) d16_30
FROM t0_samples t LEFT JOIN first_apply f USING(user_id,repaid_date) GROUP BY 1)
SELECT month,sample_cnt,ROUND(d0::numeric/sample_cnt*100,2) day0_rate,
ROUND(d1_7::numeric/sample_cnt*100,2) day1_7_rate,
ROUND(d8_15::numeric/sample_cnt*100,2) day8_15_rate,
ROUND(d16_30::numeric/sample_cnt*100,2) day16_30_rate,
ROUND((d0+d1_7)::numeric/sample_cnt*100,2) day7_cum_rate,
ROUND((d0+d1_7+d8_15)::numeric/sample_cnt*100,2) day15_cum_rate,
ROUND((d0+d1_7+d8_15+d16_30)::numeric/sample_cnt*100,2) day30_cum_rate FROM m ORDER BY month;
模块 3：当天订单整体/期次加权息费与期次结构
WITH d AS(
SELECT t.repaid_date,f.* FROM t0_samples t JOIN first_apply f USING(user_id,repaid_date)
WHERE f.first_apply_date=t.repaid_date), term AS(
SELECT TO_CHAR(DATE_TRUNC('month',repaid_date),'YYYY-MM') month,first_apply_total_term total_term,
COUNT(DISTINCT first_apply_serial_id) order_cnt,
ROUND(COUNT(DISTINCT first_apply_serial_id)::numeric/
SUM(COUNT(DISTINCT first_apply_serial_id)) OVER(PARTITION BY DATE_TRUNC('month',repaid_date))*100,2) term_share_pct,
ROUND(SUM(COALESCE(first_apply_pre_amt,0)+COALESCE(first_apply_post_amt,0))::numeric/
NULLIF(SUM(first_apply_remit_amt),0)*100,2) term_fee_pct FROM d GROUP BY 1,2,DATE_TRUNC('month',repaid_date)),
overall AS(SELECT TO_CHAR(DATE_TRUNC('month',repaid_date),'YYYY-MM') month,
ROUND(SUM(COALESCE(first_apply_pre_amt,0)+COALESCE(first_apply_post_amt,0))::numeric/
NULLIF(SUM(first_apply_remit_amt),0)*100,2) overall_fee_pct FROM d GROUP BY 1)
SELECT term.*,overall_fee_pct FROM term JOIN overall USING(month) ORDER BY month,total_term;
模块 4：历史成功放款次数分层的息费与当天提单率
-- 先执行模块1。历史次数为当前T0获额时点之前的成功放款订单数；
-- 0次和1次均归入“贷款1次”分层，与报告历史口径保持一致。
WITH history AS(
  SELECT t.user_id,t.repaid_date,
    CASE WHEN COUNT(DISTINCT h.serial_id) <= 1 THEN '贷款1次'
         WHEN COUNT(DISTINCT h.serial_id)=2 THEN '贷款2次'
         WHEN COUNT(DISTINCT h.serial_id) BETWEEN 3 AND 5 THEN '贷款3-5次'
         ELSE '贷款6次及以上' END loan_times_group
  FROM t0_samples t LEFT JOIN all_orders h ON h.user_id=t.user_id
    AND h.is_remit=1 AND h.apply_time<t.credit_vir_time
  GROUP BY 1,2
), monthly AS(
  SELECT TO_CHAR(DATE_TRUNC('month',t.repaid_date),'YYYY-MM') month,h.loan_times_group,
    COUNT(*) sample_cnt,
    ROUND(COUNT(*) FILTER(WHERE f.first_apply_date=t.repaid_date)::numeric/COUNT(*)*100,2) day0_rate_pct,
    ROUND(SUM(COALESCE(f.first_apply_pre_amt,0)+COALESCE(f.first_apply_post_amt,0))
      FILTER(WHERE f.first_apply_date=t.repaid_date AND f.first_apply_remit_amt>0)::numeric
      /NULLIF(SUM(f.first_apply_remit_amt) FILTER(WHERE f.first_apply_date=t.repaid_date AND f.first_apply_remit_amt>0),0)*100,2) fee_rate_pct
  FROM t0_samples t JOIN history h USING(user_id,repaid_date)
  LEFT JOIN first_apply f USING(user_id,repaid_date)
  GROUP BY 1,2
)
SELECT month,loan_times_group,sample_cnt,day0_rate_pct,fee_rate_pct,
  ROUND(CORR(fee_rate_pct,day0_rate_pct) OVER(PARTITION BY loan_times_group)::numeric,2) monthly_corr
FROM monthly
ORDER BY month,CASE loan_times_group WHEN '贷款1次' THEN 1 WHEN '贷款2次' THEN 2 WHEN '贷款3-5次' THEN 3 ELSE 4 END;
报告为趋势与结构性证据；如需证明价格对提单率的因果影响，须引入获额时可见报价并进行控制变量或实验分析。
